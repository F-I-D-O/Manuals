# MSBuild
[Wikipedia](https://en.wikipedia.org/wiki/MSBuild)

MSBuild is a set of tools for building software in various languages created by Microsoft. In this manual, we will only focus on .NET (managed code) projects.

The build is configured by the project (`csproj`) file.

## Project File


[Official documentation](https://learn.microsoft.com/en-us/aspnet/web-forms/overview/deployment/web-deployment-in-the-enterprise/understanding-the-project-file)

The MSBuild project is configured using the `csproj` file, which is a XML file. The file is structure is presented in the following picture:

![Project File](image2.png)
source: https://learn.microsoft.com/en-us/aspnet/web-forms/overview/deployment/web-deployment-in-the-enterprise/understanding-the-project-file

Under the root `Project` element, the project definition is divided into three types of elements:

- [`PropertyGroup`](https://learn.microsoft.com/en-us/aspnet/web-forms/overview/deployment/web-deployment-in-the-enterprise/understanding-the-project-file#properties-and-conditions): contains the properties for the project, like .NET version
- [`ItemGroup`](https://learn.microsoft.com/en-us/aspnet/web-forms/overview/deployment/web-deployment-in-the-enterprise/understanding-the-project-file#items-and-item-groups): contains the items for the project, like source files, dependencies, etc.
- [`Target`](https://learn.microsoft.com/en-us/aspnet/web-forms/overview/deployment/web-deployment-in-the-enterprise/understanding-the-project-file#targets-and-tasks): build target specification

Unlike in C++, project files does not have to be listed in the `csproj` file. All files in the same directory tree as the `csproj` file are automatically included in the project.


# Running .NET Projects
The project can be run using the [`dotnet run`](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-run) command. This command handles both build and run. Internally, it uses the `dotnet build` command to build the project, and then runs the executable produced by the build.

Important arguments:

- `--project <path>`: specify the path to the project file (defaults to the current directory)



# `global.json`: specify the .NET SDK for build
[Official documentation](https://learn.microsoft.com/en-us/dotnet/core/tools/global-json)

To specify the .NET SDK version acceptable for the build, we can use the `global.json` file. The format is:
```json
{
  "sdk": {
    "version": "<version>",
    "rollForward": "<forward specification>"
  }
}
```

The `<forward specification>` is optional and specifies the version selection logic. The possible values are:

- `disable`: exact version is required
- `<semantic version part>`: if desired version is not available, go to the next version, based on the specified `<semantic version part>`
- `latest<semantic version part>`: go to the latest version, based on the specified `<semantic version part>`

The `<semantic version part>` can be:

- `feature`: only feature part can differ (i.e., `<specified major>.<specified minor>.<next/latest feature>`)
- `minor`: only minor and feature parts can differ (i.e., `<specified major>.<next/latest minor>.<next/latest feature>`)
- `major`: all parts of the version can differ (i.e., `<next/latest major>.<next/latest minor>.<next/latest feature>`)

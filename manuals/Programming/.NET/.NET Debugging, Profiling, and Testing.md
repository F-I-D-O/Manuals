# Testing
[Official documentation](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test)

Tests are run using the `dotnet test` command. By default, the VSTest runner is used, we can also configure the Microsoft Testing Platform (MTP) to run the tests.

The available arguments depend on the test runner (VSTest or MTP), but also on the test framework used. There are three main test frameworks:

- MSTest,
- xUnit, and
- NUnit

## VSTest
[Official documentation](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test-vstest)

The most commonly used arguments are:

- `--filter <filter>`: filter tests


### Filtering
[Official documentation](https://learn.microsoft.com/en-us/dotnet/core/testing/selective-unit-tests)

We filter tests using `--filter <filter>`, where `<filter>` is in the form `<property><operator><value>`.

The `<property>` can be either `FullyQualifiedName`: the fully qualified name of the test, or some other property specific to the test framework used:

- xUnit: 
    - `<Trait>`: any trait defined in the trait annotation can be used. If the annotation is `Trait("Category", "Integration")`, the test can be filtered using `--filter Category=Integration`


### Controlling the verbosity of the output
We can set the verbosity of the output on two layers:

- `--logger:<logger>;verbosity=<verbosity>`: set the verbosity of the test framework output
- `-v <verbosity>`, `--verbosity <verbosity>`: set the verbosity of VSTest output

Both layers use the same [verbosity levels](https://learn.microsoft.com/en-us/dotnet/api/microsoft.build.framework.loggerverbosity?view=msbuild-18-netcore).
